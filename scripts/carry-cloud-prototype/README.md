# Carry 账户数据风险原型

用途：在改造真实账户/同步前，用合成数据验证冲突、事务、回执和删除契约。只使用 Node 自带 SQLite，无外部依赖，无 HTTP 服务、云配置、真实 Apple 登录或用户数据库路径。

运行：Node 24+，在本目录执行 `npm test`。本机可用 Node 为 `/Users/murphy/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node`，也可用该路径直接执行 `--test *.test.mjs`。

每个用例创建独立的临时磁盘 SQLite，完成后关闭并删除。覆盖：

- 服务端式数据保存与重启读回，不调用手机或当前远程 MCP。
- 两份基于同版本的离线修改：不同字段保留，争用字段返回双方内容。
- 整套行程写入在无效子项或提交故障时全部回滚，回执和变更流也不泄漏部分成功。
- 重试请求稳定读回同一回执，同 ID 改内容拒绝。
- 账户维度寻址、父子归属、历史分页、删除后拒绝旧编辑复活。
- 日期合法性和明确的打包状态。
- 合成文件全部校验后才发布目标目录；后一个文件损坏时不留部分成功，不修改源文件。重复名字与路径越界在创建临时目录前拒绝。

**边界**：这是算法风险验证，account 参数由可信测试用例提供，不是认证机制；没有 API 层、权限凭据、真正多进程并发、原生持久 outbox、实际应用的完整文件/图迁移、全量重同步、数据保留清理或全部 Carry 业务规则。文件实验只处理合成平铺文件，不包含生产的账号归属、并发目标保护、容量/流式传输限制或断点续传。只覆盖 trip/stop/packingItem 的最小字段。父项带子项时拒绝删除，尚未实现整棵图的删除/撤销产品语义。不能作为完整同步或账号安全验收，也不能直接部署/接用户数据。

在采用 Postgres/同步服务后，需要在实际数据库、真实原生设备和认证路径重跑契约。SQLite 本地测试通过不证明候选供应商网络可达，也不等于 App 已支持手机关闭时的 Codex 操作。
