# Account-side queries

`createAccountQueries` is installed by `runtime.mjs` without a phone executor. It receives only the already-authorized/redacted graph and the explicit query input. Query results are untrusted provider data and never mutate the account. Creating or reordering a trip still requires the existing account command/preview flow.

## Tools

- `search_airports`: `{query,language?,limit?}`; lazy-loads the exact `Carry/Resources/airports.json` native catalog, uses native score ordering and multilingual aliases, returns at most100 records. IANA time zones come from the physical coordinate lookup rather than stale provider timezone strings; mainland countries canonicalize to Asia/Shanghai.
- `search_places`: `{countryCode?,query?,placeID?,session?,proximity?:{latitude,longitude},city?,language?,limit?}`. The known trip's primary/additional structured destination countries bind a trip-scoped request; unknown-country relabelling is rejected. Querying a new destination before editing the trip can omit tripID and explicitly supply its country. Coordinates in domestic IANA zones cannot be labelled overseas. Domestic CN/HK/MO requests use only Amap's fixed Web Service API origin; no overseas proxy fallback. The overseas path uses existing Carry suggest/retrieve endpoints; suggestions contain no resolved coordinate, so retrieval is mandatory before storing a result. Retrieved country and coordinate timezone are verified again. Geoapify packed identifiers cannot bypass this check.
- `lookup_flight`: `{number,date}`; exact flight-number/date parameters only go to the existing Carry flight proxy. Results are bounded and projected to known fields, not arbitrary provider JSON. Empty flights means provider returned an actual empty list; configuration/outage/throttling/malformed responses remain distinct failures.
- `preview_route`: either `{dayID}` from the scoped graph, or `{stops:[{id,latitude,longitude}]}`. Native Haversine nearest-neighbor and bounded2-opt preserve first/last anchors. At most100 stops. Result is explicitly `great_circle_estimate`, has no road distance or duration, and applies no reorder. This mirrors the native optimizer's sorting basis; MapKit road/traffic directions are device-only and are not fabricated server-side.
- `get_packing_recommendations`: `{scenes?,tripDays?,isInternational?,destinationCodes?,storefront?,language?,departureDate?,rankingMode?,supplementaryLimit?}`. Scene base items, quantities, category ordering, supplementary recommendation scoring/overlap/scene guardrails, climate sets and translated labels are generated from native sources. Explicit storefront controls travel-document rules; locale is never treated as storefront. A local YYYY-MM-DD departureDate is required for seasonal inference, avoiding guessed device timezones. Climate suggestions do not silently change the chosen scene list. Default destination countries include the trip’s primary and all structured additional destinations. Mixed Hong Kong/Macao/Taiwan and overseas trips retain the passport alongside their permits. Existing-item checks use only the specified trip. Personal period/medication inference is refused; no HealthKit data is used.

Network responses are bounded to1MiB, with a15-second deadline, no redirect following, cancellation, validated shape and no forwarding of OAuth bearers or full trips. Server settings select upstream origins; tools cannot supply a URL. Production Amap origin must be restapi.amap.com. Explicit loopback mode is only for synthetic tests.

## Configuration and remaining hosted acceptance

Deno entry reads server-only `CARRY_FLIGHT_APP_TOKEN`, `CARRY_PLACES_APP_TOKEN` and `CARRY_AMAP_WEB_KEY`. Flight/places tokens reuse the existing Carry proxy contract; Amap requires a separately provisioned Web Service key. No new key was created, no account data was uploaded and no live paid provider request was performed in local tests. Missing settings return concrete `*_configuration_required` responses rather than an empty success. Existing overseas providers and translation policy remain those of the Carry places Worker.

Amap's returned domestic coordinates are explicitly GCJ-02, as used by native mainland map paths. Overseas/airport coordinates are WGS-84. Consumers must preserve that distinction; this module does not silently transform/replace graph coordinates. Provider configuration, entitlements and actual network reachability still require hosted acceptance.

Official Amap request contract checked against https://developer.amap.com/api/webservice/guide/api/search/ and https://developer.amap.com/api/webservice/guide/api-advanced/search . Existing flight/overseas contracts are the repository's `scripts/flight-proxy/worker.js` and `scripts/places-proxy/worker.js`.

## Rule generation and evidence

Run `node query-data-generator.mjs` after native recommendation changes. `queries.test.mjs` regenerates the value in memory and compares it with the checked-in manifest, so source/label/ranking drift cannot silently pass. Runtime data is private-data-free bundled reference material. `tz-lookup`6.1.25 is locked in this package. Tests cover actual bundled airports, native recommendation output, physical-country policy, fixed-origin proxy contracts, actual loopback HTTP, MCP authorization before query IO, cancellation, chunked limits and negative provider paths. Those are local synthetic tests; they do not establish live provider reachability or phone UI behavior.
