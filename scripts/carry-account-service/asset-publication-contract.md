# Native asset publication

Private assets are immutable, account/entity/slot-bound objects. Native preparation snapshots bytes into the account cache before the journal bridge commits metadata. Scalar edits do no file work. The RAW transaction writes the binding, queued upload and corresponding graph field intent together. A missing source defers the immutable journal; it never substitutes a filename for verified bytes.

`fileAssetID`, `thumbnailAssetID` and optional photo `originalAssetID` are UUID references. Optional trip `backgroundAssetIDs` is a bounded object (maximum 256 entries), keyed by `background:<destinationIndex>:<entryIndex>` and valued by asset UUID. These keys preserve the relationship to `backgroundsData`; a flat array would lose it. Slot components are decimal integers of one to four digits. Binary bytes are not embedded into these fields.

`CarryNativeAssetCoordinator.preparePublication` pins referenced local jobs to the frozen request ID, resumes reserve/upload/server verification, and refuses publication until every referenced job is verified. An already-remote reference requires explicit trusted verification; absence from the local queue is never proof of upload. Final receipt acceptance releases request pins. Prepared but uncommitted bytes remain in `preparedTokens`. Physical GC must share the workspace ingestion/sync gate and retain native, journal, queued and frozen references; `isBusy == false` is not by itself authorization to collect.

The PostgreSQL `graph_verified_asset_references` trigger validates every live inserted/changed/restored graph row. It applies to native commands, staged commands and the shared AI core, including children restored by an ancestor operation. References must match the exact account, entity, kind and slot; the asset ledger must be verified and its verified version must still name the current non-archived provider object. Pending, deleting, missing, other-account/entity/slot and superseded references fail the whole transaction with `asset_reference_unverified`. Pure metadata changes skip redundant asset checks. Deletion remains possible if bytes are missing; restoration requires bytes again. The trigger uses the account advisory lock shared by graph writes, upload verification, cleanup and account deletion.

The ledger retains verified bytes during ordinary use. This change does not introduce a new physical garbage collector, expose Storage policies, or permit clients to certify bytes. Account deletion continues using the existing server cleanup lifecycle. Deployment and end-to-end UI acceptance remain separate from local contract tests.

A nonempty attachment `fileName` requires `fileAssetID`. For trip backgrounds the server also decodes the bounded native base64 JSON list, validates its source/filename/destination shape, and requires the exact background-slot key set. This prevents accepting a graph that the native projector can never materialize because only device-local filenames were published.
