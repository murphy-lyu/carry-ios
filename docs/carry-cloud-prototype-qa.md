# Carry 账户数据风险原型验证

日期：2026-10-25。范围：`scripts/carry-cloud-prototype`；独立本机合成数据，不访问现有 App 容器、iCloud、远程 MCP 或认证服务。

## 结果

两轮完整算法回归均 **14/14、0 失败、0 跳过**。第一轮逐项结果已在本任务工具输出保留，第二轮日志：`/tmp/carry-cloud-prototype-final-round2-20261025.log`。另有开发中的 11 项数据事务回归；增加合成文件实验后按完整 14 项重新运行两轮。

| 检查 | 证据 |
|---|---|
| 保存与进程式重建 | 关闭磁盘 SQLite，重新打开后对象和幂等回执仍在，无手机调用 |
| 两份离线意图 | 相同基准版本、不同字段合并；同字段返回双方值，失败不推进版本/变更流 |
| 整套计划失败 | 无效后续子项使前面的行程/地点、变更流和回执全部回滚 |
| 提交故障 | 事务提交前注入异常，重开数据库无对象/成功回执，同 ID 后续可重新成功 |
| 丢失响应/重复请求 | 重开数据库后复用同请求 ID，回执相同、行数/变更数不增加；改内容拒绝 |
| 账户寻址 | 相同对象 ID 在两个合成账户隔离，跨账户更新和父项引用失败；这不验证实际鉴权 |
| 删除 | 删除标记重开仍在，旧离线修改及同 ID 重建拒绝；父项带子项拒绝，避免原型产生孤儿 |
| 拉取重放 | 账户范围分页与重复读取一致，尚未模拟真实客户端游标持久化 |
| 领域小样本 | 非法日历日期/倒序拒绝，明确 isPacked 设置的重试不反转状态 |
| 文件实验 | 全部校验才发布目录；后续文件损坏不发布部分数据，源文件不变，重复命名与越界路径拒绝 |

## 自行 Review

- 逐条核对业务数据、回执、变更流共处一个 SQLite 事务；异常后 rollback，重试摘要按稳定字段序列化。
- 冲突比较字段的最后服务端版本与编辑基准，无本地时钟优先规则；版本不能指向未来。父子归属按同一账户查询。
- 文件实验只操作测试新建目录和纯合成字节，校验源/复制后 SHA256、长度，失败清理自己新建的 staging，不改源。
- 核对运行范围：未新增 HTTP 入口，未加入生产 App/Worker 构建或生产部署配置，无密钥/外部依赖/网络请求。没有假造 Apple 登录或用参数账户 ID 冒充已鉴权身份。

## 必须保留的边界

这是算法原型，不是服务商选定后的生产实现，不是完整 SwiftData 同步。尚未覆盖原生事务 outbox、真实双进程冲突、领域完整图/排序、文件流式断点传输、附件权限、数据库恢复演练、墓碑清理、账号删除/实际鉴权及手机关闭时真实 MCP API 往返。

原型的文件发布也不具备生产并发目标保护、配额/大小限制；不得直接用于真实旅行迁移。实际账号验证、Postgres/候选同步 SDK 和原生设备必须分别过契约与完整验收。旧实现 39 项原生测试的结果仍属于旧实现，不能与此处 14 项相加描述成新架构已通过完整验收。
