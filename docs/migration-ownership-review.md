# 原生迁移归属与源保护 Review

本地实现范围：显式选择旧行程与物品库、完整备份和原图收集、持久迁移任务、核验后切换原生数据归属、只读源保护、旧设备变更比较及保留两个版本。未执行真实账户上传或云端部署。

## 已修复的问题

- 暂停普通同步后的输入错误、缺失任务、构造失败均经统一恢复路径退出；用户取消等待迁移任务结束后恢复普通同步。关闭账户或挂起工作区会再次暂停，不会被迁移退出回调重新开启。
- SQLite 的迁移核验完成后，先同步并检查账户原生模型已包含全部根记录，再发布首页归属索引及“完成”状态。启动恢复索引同样检查原生模型，避免崩溃后隐藏唯一可读的本地版本。
- 已迁原记录和待处理源均由保存入口的写入守卫保护；新增子记录、移动旧子记录、独立自动化上下文均经过同一检查。iCloud 传入的旧设备修改保留为可比较的分叉。
- 文件保留索引覆盖源与已复核的新源引用。恢复副本保留完整业务字段并重分配所有实体 ID；共享的不可变文件受到保留保护，删除副本文件不会删除源文件。
- 物品库展示和分类批量操作使用可见记录，保留原始物品库供备份和源恢复。已迁项目不会因退出登录重新显示为可编辑数据，待核验的账户库项也不会提前显示。
- 迁移入口拒绝再次迁移受保护源；保留两个版本需要与界面展示相同的不可变复核快照，且本地上下文无未保存改动。源已删除时只保留账户计划及本地删除结果，不创建空副本。
- 原图缺失或照片权限不足会明确失败，不使用缩略图代替。附件单文件上限 25 MiB，原图和背景单文件上限 50 MiB，批次内嵌预算为 128 MiB；超限需缩小文件或减少行程选择。原图按文件流式落盘，避免整个相册驻留内存。

## 自动验证入口

- `MigrationOwnershipTests`：源指纹、只读写入门、全字段恢复副本、账户物化前后归属与退出登录、索引账户隔离。
- `AccountWorkspaceControllerTests`：原有账户生命周期验证，以及无效选择、暂停后缺失任务、脏源拒绝、显式迁移完整投影后切归属的回归测试。
- 迁移引擎、备份原图、实际 HTTP 与图协议测试由统一测试任务执行，结果以该轮日志为准；本文件不替代运行结果。
- 稳定恢复副本 ID 由批次、源指纹、原实体 ID 派生；重试复用完整且未编辑的副本，已编辑副本不覆盖。复核前后的源快照和实际复制证据必须完全一致。差异界面展示业务值前后对照，文件及父级关系不会泄露原生路径或 ID。
- 九语言新增文案位于 `docs/localization/carry-account-migration.xcstrings.json`，供最终统一合入 catalog。

## 验证边界

Photos 系统流式写入接口不提供取消句柄。用户取消后会等待当前原图落盘，随后检查取消并停止；该等待阶段不会发布账户图或切换归属。需要真实设备验收系统照片授权、iCloud 原图下载及界面显示；本地代码和自动测试不能代替这些检查。

## 网络提交与本机归属时序

用户初次明确确认后，服务端整批提交的快照就是完整有效的账户版本。服务端提交与本机原生模型投影、旧源归属切换属于不同阶段；本地核验未完成时，账户中的已提交快照仍可用于 AI 操作。源后来被旧设备修改时，差异复核决定本机如何保留两个版本，不撤销先前已明确授权的账户快照。没有额外实现跨库提交协议，也没有宣称 AI 会隐藏已提交的快照。

## 本轮审查处置

暂停恢复、首次物化、隐藏物品库、重复迁移、动态源文件保留、崩溃后恢复副本重试及复核快照时序问题均已修复，并增加相应自动回归入口。自动测试执行结果由统一监督任务记录，当前文档不提前宣称全部通过。首页副本名称保持原名；目前使用迁移页面说明“本地可编辑副本”与“只读原记录”，未新增首页标签。系统 Photos 授权和原图下载的真机验证仍保留为设备检查，不影响继续执行本地代码验证。

## 新设备重号恢复的本地采用流程

已补上可直接用临时 SQLite 和只读传输复现的第二设备问题：相同 iCloud 旧源 UUID 与账户原生投影同时存在时，账户工作区仍可挂载并进入显式复核；未复核的账户冲突根隔离，不自动选取可编辑账户版本。

本机采用采用独立的 `CarryAccountLocalAdoptionRecord`，不伪造迁移批次或回执。账户目标子树按根范围读取，只核对目标实体的认证观察状态、原生物化基线、资源绑定、槽位和缓存字节。每张照片必须有原图；附件、背景与缩略图所需槽位严格对应。无关损坏账户 payload 不参与所选内容的验证。

用户确认后先生成完整私人备份及原图边车，后台逐文件哈希验证并发出类型化归档凭据，再持久化待处理索引，保存稳定新 UUID 的完整本机副本，最后核对源、副本和账户证据并激活。恢复逻辑不构造账户 apply 命令，也不以通用 synchronize 代替只读证据验证。退出恢复流程时恢复常规同步；此前用户保存的独立待同步编辑仍按原协议处理。失败后可以继续复核；取消未完成的本机切换会恢复源可编辑，保留所有备份、已生成副本和账户数据。

恢复 UUID 的命名空间是各设备／安装的账户私有缓存中持久随机 `localRecoveryNamespace`，不是共享账户 ID。同一缓存重开、重试稳定；两个设备即使账户和旧源完全相同，也不会生成相同业务 UUID。已激活账户版本被正常删除时，只有认证 tombstone、无原生根、完整已物化删除基线及无目标待发送变更同时成立才保留删除归属，避免历史只读源自动复活。

`LocalAdoptionTests` 提供 18 项本地回归，包括首次和冷启动重号、行程／物品库、源或账户变化、脏／缺失原生投影、缺原图／字节／错误绑定、归档篡改、取消恢复编辑、跨缓存身份及无关坏记录。运行结果由统一测试日志记录，真实多设备界面与 iCloud 传输仍保留为设备验收。

补充收尾：本机选定根按实际 UUID 分批查询并进行可抛错去重；同 UUID 多条 iCloud 记录安全报错，不使用可能触发进程 trap 的唯一字典构造。无关重复根和无关损坏背景不参与所选复核。稳定归档重试保留首次真实备份时间及当时全局偏好，仅当所选图与文件内容完全一致才复用；新读到的原图仍逐 SHA 核验。测试中账户新版本先通过暂停旧同步轮次、开启新轮次，并核对原生字段、raw cursor 与物化基线版本，再验证陈旧复核必定拒绝。
