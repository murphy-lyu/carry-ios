# 原生账户库与现有旅行界面的接入
日期：2026-10-29。状态：已批准云同步范围内的实施细化，以下接入尚未完成，不能当作当前运行行为。

## 已核对的入口
- `ContentView.swift` 三个实际入口创建 `PackingListView`，含新行程路径；详情以下的编辑、停靠点、交通、住宿与打包页面继承 TripStore 环境对象。
- `TripStore` 当前持有单个 ModelContext，并有多条直接 save、自动地理回填和独立自动化事务；只修改普通 save 方法会漏掉写入。
- `DataBackupManager` 有三条最终 context.save 路径，导入/还原必须把业务投影和账户 outbox 放进同一保存，不能在导入完成后另补同步请求。
- View 层初查未发现直接 SwiftData insert/save/delete；附件/背景文件有独立写入/删除，需要单独纳入事务后回收及资产队列。全调用点审计仍在继续。

## 实施约束
保留原本地/iCloud TripStore；每个 Carry 账户使用 CloudKit.none 的独立容器。账户容器复用现有业务模型和 TripStore 方法，在实际详情入口注入对应 store，避免把账号元数据塞进 CloudKit SchemaV1。首页聚合当前身份可见的来源；迁移归属标记只隐藏已确认迁入的源图，不静默删除 iCloud 数据。

每个账户 store 显式注入持久化入口，所有保存、导入、还原和自动回填都经过它。业务改动与 outbox 在同一个 context/save 提交；账户 context 关闭 autosave。不能用“保存后监听再排队”代替原子提交，也不以无法向调用者传播错误的 willSave 通知作为唯一写入门。

账户子 store 的通知、Widget、Live Activity 等全局副作用由根库统一调度，使用所有可见行程；不能让两个 store 分别重排全局通知而互相清空。首页删除/复制、新建、分享导入、Siri、全局备份与物品库逐项路由，旧设备执行器不获得新账户行程。

本地字段捕获按实际变化实体处理，避免每次打包勾选编码整份备份或读所有附件。照片/附件上传准备、摘要与网络放到资产队列；只有已验证资产才发布引用。磁盘文件必须保留到本地事务提交及相关在途操作结束，不能在删除模型前先删唯一文件。

当前协议一次最多 500 个 mutation，不能把更大的迁移拆成对外可见的半套行程。需要有界分块暂存、完整校验后单事务提交，以及分页读取同一不可变回执；普通 API 的 500 项上限继续保留。

退出与换账户前暂停旧同步/上传，隔离保留待同步编辑；导航不继续展示另一身份的模型。删除账户完成后的本机缓存与未同步编辑处理必须独立验收，不清除原本地/iCloud 行程。

## 捕获与投影的补充约束
原生投影须保存最后实际显示/落盘的字段快照。收集本地改动时只把相对该快照真正变化的字段写入 replica，不能把延迟投影期间尚未显示的远端字段用旧界面值覆盖。网络分页先进入持久 replica，捕获本地意图后，完成一轮补齐再原子投影到业务模型；不要逐页展示半套新行程。

现有 graph_record 为每个子项保存全量祖先快照，遇到较大的背景/提醒元数据会重复传输。后续改为保留连续序号的 metadata-only 祖先事件，客户端用已有完整对象核对并补全，不能通过删掉序号或随意跳游标优化。

Replica 当前只实现 create/patch/move；原生删除/恢复还需持久的子树预览基线、在途 create/delete 后的反向意图、离线撤销及祖先删除期间的子项处理。不能直接删业务模型后另发无版本 DELETE。
